<Box type="point" title="先に結論">

## 独自ドメインとは

独自ドメインは、「ai-raku-note.com」のような、自分だけのサイトのアドレスです。

このブログは GitHub Pages という無料の仕組みで公開しています。独自ドメインがなくても公開はできますが、アドレスが「(ユーザー名).github.io/(リポジトリ名)」のような長いものになります。

独自ドメインにすると、アドレスが短く覚えやすくなります。あとで公開先を変えても、アドレスはそのまま使えます。

## 僕が XServerドメインにした理由

決め手は値段でした。はじめての人なら、.com が0円で取れたからです。

2年目からの更新料金は1,721円で、ムームードメインとほぼ同じです。お名前.com の表示価格よりは313円高くなります。XServerドメインは、料金ページに「表示料金のほかに追加の費用はかからない」と書いてあります。

もう一つ、あとから良かったと思ったのは、DNS の設定（ドメインとサイトをつなぐ設定）を、管理画面から自分で書けることです。GitHub Pages のような外のサービスにつなぐときは、この設定が必ず要ります。

## 取り方の手順

1. XServerドメインの公式サイトで、欲しい名前を検索する。空いていれば申し込める
2. 申し込みの画面で、アカウントを作って支払いを済ませる（0円のときも手続きは同じ）
3. 申し込みが終わると、管理画面にドメインが並ぶ

ここまでは、迷うところがほとんどありませんでした。

## GitHub Pages につなぐ設定

ドメインを取っただけでは、サイトは開きません。「このアドレスに来た人を、GitHub Pages のサイトに案内する」という設定を、ドメイン側と GitHub 側の両方でします。

### ドメイン側：DNS レコードを足す

XServerドメインの管理画面で「DNSレコード設定」を開き、次の5行を足します。

| ホスト名 | 種別 | 内容 |
| --- | --- | --- |
| （空のまま） | A | 185.199.108.153 |
| （空のまま） | A | 185.199.109.153 |
| （空のまま） | A | 185.199.110.153 |
| （空のまま） | A | 185.199.111.153 |
| www | CNAME | (GitHub のユーザー名).github.io |

A の4行は、GitHub Pages のサーバーの場所です。www の行は、「www.」を付けて開いた人も同じサイトに案内するためのものです。

### GitHub 側：独自ドメインを登録する

GitHub のリポジトリの「Settings」→「Pages」を開き、「Custom domain」に取ったドメインを入れて保存します。DNS の設定が正しければ、確認が通ったことを示す表示が出ます。

## 僕がつまずいた3つのこと

### 1. ネームサーバーの指定先がちがって、一晩たっても開かなかった

DNS レコードを足して一晩待っても、サイトは開きませんでした。調べてみると、DNS レコードを書いた先と、ドメインが実際に使っている「ネームサーバー」が食いちがっていました。

ネームサーバーは、DNS レコードがどこに書いてあるかを世界に知らせる仕組みです。僕のドメインは、ネームサーバーが **NS1〜NS5.XSERVER.JP** になっていました。これは、レンタルサーバー「エックスサーバー」で使うためのものです。DNS レコードを書いたのは XServerドメイン側です。ネームサーバーがそちらを指していないと、せっかく書いた設定が読まれません。

XServerドメインの「ネームサーバー設定」を **NS1〜NS3.XDOMAIN.NE.JP**（XServerドメインのネームサーバー）に変えると、その日のうちに開くようになりました。

<Box type="warn" title="レンタルサーバーを使わないなら">
GitHub Pages のような外のサービスにつなぐときは、ネームサーバーが「XDOMAIN.NE.JP」になっているかを最初に確かめてください。DNS レコードの画面がいくら正しくても、ここがちがうと開きません。
</Box>

### 2. HTTPS（鍵マーク）が使えるまで数時間かかった

サイトが開くようになっても、しばらくは「http://」でしか開けませんでした。GitHub が、ドメインに合わせた証明書（鍵マークに必要なもの）を作るのに時間がかかるためです。

GitHub の説明では、長いと24時間ほどかかることがあります。僕の場合は、DNS を直してから数時間でできました。「Settings」→「Pages」の「Enforce HTTPS」にチェックを入れられるようになったら、できた合図です。チェックを入れると、http で来た人も https に切り替わります。

### 3. Search Console の確認が、1回目は失敗した

検索に載せてもらうため、Google の Search Console にも登録しました。登録では、Google が出す確認用の文字列を、DNS レコードの「TXT」として足します。

足してすぐに「確認」を押すと、「所有権を証明できませんでした」と出ました。XServerドメインのネームサーバーは複数台あり、新しいレコードが全部に行き渡るまで少し時間がかかります。Google が、まだ届いていないほうに問い合わせたのだと思います。

レコードには触らずに少し待ってから押し直すと、確認が通りました。エラーが出ても、慌ててレコードを消したり足したりしないのがコツです。
