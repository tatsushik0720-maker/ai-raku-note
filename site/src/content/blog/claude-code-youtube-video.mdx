僕は YouTube チャンネル「[【歴史解説】138億年の旅](https://www.youtube.com/@138okunen)」で、歴史と科学の解説動画を出しています。顔も声も出していません。ナレーションは VOICEVOX の声です。

動画は、Claude Code に作ってもらっています。テーマを1行渡すと、台本からサムネイルまでひと通り出てくる仕組みです。仕組みそのものも、Claude Code と相談しながら数日で作りました。

ただし、ボタン1つで完成するわけではありません。出てきたものを見て、何度か直しを頼みます。それでも、1人で全部作るのとは比べものにならないくらいラクになりました。

<Box type="point" title="先に結論">
- テーマを1行渡すと、台本 → ナレーション → 映像 → 編集 → サムネイル → 概要欄まで、Claude Code が順に作る
- 道具は、Claude Code・VOICEVOX（声）・Remotion（映像）・ffmpeg（つなぎ合わせ）。Claude Code の有料プラン以外は無料で使っている
- いちばん苦労したのは映像の見た目。止め絵をゆっくり動かすだけの動画では、見ていて飽きる
- 「量産っぽく見えないこと」を仕組みの決まりに入れた。前の動画と、構成・つかみ・サムネの型をかぶらせない
</Box>

## 作った仕組みの全体

1本の動画ができるまでの流れは、こうなっています。

| 順番 | すること | 使う道具 |
| --- | --- | --- |
| 1 | テーマから台本を書く | Claude Code |
| 2 | 台本の事実と言い回しを、別の担当が確かめる | Claude Code（確認用の別の AI） |
| 3 | ナレーションの読みを確かめてから、声を作る | VOICEVOX |
| 4 | BGM をつけ、映像を作る | Remotion など |
| 5 | 確認版から切り出した画像を見て直し、本番を書き出す | ffmpeg |
| 6 | サムネイル、ショート、概要欄を作る | Claude Code |

僕がするのは、最初にテーマを1行渡すことと、途中と最後の確認です。たとえば「古代ローマの1日」と渡すと、靴職人の1日を追いかける構成の台本から始まります。

Claude Code は、パソコンの中でファイルを作ったり、コマンドを動かしたりできる AI です。チャットで答えるだけの AI とちがい、台本を書いたあとに声を作るプログラムを動かせます。映像の書き出しまで自分で進められます。この「手を動かせる」ところが、動画づくりと相性がよかったんです。始め方は「[Claude Code の始め方【Windows】](/blog/claude-code-windows-start/)」にまとめています。

## 使っている道具

| 道具 | 役割 | 料金・条件 |
| --- | --- | --- |
| Claude Code | 台本・映像のコード・サムネ・全体の進行 | 有料プラン（Pro は月20ドル） |
| VOICEVOX | ナレーションの声 | 無料。商用でも使えるが、クレジット表記が必要 |
| Remotion | 数字や図が動く映像をコードで作る | 個人と3人までの会社は無料 |
| ffmpeg | 声・映像・BGM をつなぎ合わせる | 無料 |

（VOICEVOX の利用規約と Remotion のライセンスは2026年11月6日、Claude の料金は11月7日に公式サイトで確認）

VOICEVOX は、声ごとにキャラクターの利用規約があります。動画の概要欄には、使った声の名前をクレジットとして必ず書いています。

## いちばん苦労したのは、映像の見た目

仕組みを作り始めたころの動画は、絵を1枚出して、ゆっくり拡大したり横に動かしたりするだけでした。止め絵が続くと、見ている側はすぐ飽きます。

映像の作り方は、3つの方向で変えました。

1. **動く場面は、コードで1コマずつ描いた映像にする。** 噴火、潜水艦、中世の町のような場面を、止め絵ではなく動く映像として作る。いまは、どのシーンにも1つは入れる決まりにしています
2. **数字や図は Remotion で動かす。** 数字がカウントアップする、地図にピンが立つ、年表に出来事が並ぶ。説明の中身を「動き」で見せると、ナレーションだけより頭に入りやすくなりました
3. **完成度の基準を1本決める。** 1分の短いアニメを作ったとき、背景を奥行きのある層に分け、光や粒子を重ねて、見ごたえのあるものになりました。それを「この水準で作る」という基準にして、手順も書き残しました

<Box type="memo" title="Remotion とは">
React（Web の画面を作る仕組み）で、動画をコードとして書けるツールです。「このフレームでこの数字を出す」とコードで書くので、ナレーションの時刻にぴったり合わせて図を動かせます。コードは Claude Code に書いてもらっています。
</Box>

## 量産っぽく見えないようにした工夫

AI で動画を作ると、毎回同じ構成、同じサムネ、同じ言い回しになりがちです。それでは見る人も飽きるし、作っている僕も面白くありません。そこで、次のことを仕組みの決まりに入れました。

- **前の動画と型を変える。** 「制作記録」というメモに、1本ごとの構成の型・最初の15秒のつかみ・BGM・サムネの型を残しています。新しい動画は、直近2本とかぶらないように選びます
- **構成の型を使い分ける。** 年表の旅、ランキング、その時代の1人の目線で歩く、もしも、など。これまでの動画も、全部ちがう型で作りました
- **語りか、2人の掛け合いかを選ぶ。** 「もしも恐竜が絶滅していなかったら」の回は、説明役と質問役の2人が話す形にしました。疑問が出やすいテーマは、掛け合いのほうがわかりやすくなります
- **AI っぽい言い回しを使わない。** 「いかがでしたか」で締めない、毎文同じ語尾にしない、という決まりを台本に当てています

<Box type="warn" title="事実のまちがいも別に確かめる">
年代や数字のまちがいは、解説動画ではいちばん信用を落とします。台本を書いたあと、事実を Web で確かめる担当と、言い回しを見る担当を別に立てます。指摘をもらってから直しています。
</Box>

## ナレーションの読みは、作る前に確かめる

VOICEVOX は自然に読んでくれますが、漢字の読みをまちがえることがあります。たとえば「帝」のつく語を「ミカド」と読んだり、「遠くはなれた」の「は」を「わ」と読んだりします。

声を作る前に、全文の読みをカタカナで書き出して確かめる手順を入れました。まちがえる語は、台本にひらがなの読みを足して直します。字幕は漢字のまま出るので、見た目は変わりません。

## これから試したい人へ

最初から全部をそろえる必要はありません。僕も、最初は止め絵と声だけの動画から始めました。

1. Claude Code を入れて、台本を1本書いてもらう
2. VOICEVOX で、台本を読ませてみる
3. 慣れてきたら、映像やサムネを1つずつ足していく
