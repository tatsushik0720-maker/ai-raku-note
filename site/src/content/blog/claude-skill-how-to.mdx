シフト家計簿というアプリを作ったとき、iPhone で開くと画面の下に余白が出ました。直すまでに、何度も公開し直しています。次のアプリで同じことをくり返したくなかったので、直し方を Claude Code の「スキル」にまとめました。2つ目のアプリは、最初から全画面で開いたんです。

それから、動画づくりやメモの保存など、くり返す作業をスキルにしてきました。自分用に作ったものは、いま11個あります。

<Box type="point" title="先に結論">
- スキルは、作業の手順を書いた `SKILL.md` というファイル。フォルダに1つ置くだけで使える
- いちばん大事なのは、先頭に書く説明文（description）。Claude はこれを見て、スキルを使うかどうかを決める
- 本文は短くして、細かい資料やスクリプトは別のファイルに分ける。公式の目安は500行未満
- スキルにするのは、2回以上くり返す手順だけ。一度きりの作業は、その場で頼めば足りる
</Box>

スキルの仕様は、2026年11月26日に Claude Code の公式ドキュメント「[Claude をスキルで拡張する](https://code.claude.com/docs/ja/skills)」で確かめました。

## スキルとは

スキルは、Claude Code に「この作業はこの手順で」と教えておく仕組みです。手順を `SKILL.md` に書いておくと、関係のある依頼が来たときに Claude がそれを読んで動きます。`/スキル名` と打てば、自分で呼び出せます。

似たものに、毎回読み込まれる `CLAUDE.md` があります。公式ドキュメントの説明をもとに、違いを表にしました。

| | CLAUDE.md | スキル |
| --- | --- | --- |
| 読み込まれるとき | 毎回 | 説明文だけ毎回。本文は使うときだけ |
| 向いている中身 | いつも守る決まり、事実 | 作業ごとの手順、チェックリスト |
| 長い資料 | 入れるほど毎回の負担になる | 使うときまで、ほとんど負担にならない |

公式ドキュメントは、スキルを作る目安を2つ挙げています。1つは、同じ手順をチャットに何度も貼っているとき。もう1つは、CLAUDE.md の一部が決まりではなく手順になってきたときです。

## 作り方は3ステップ

### 1. フォルダを作る

置き場所で、どこで使えるかが変わります。

| 置き場所 | 使える範囲 |
| --- | --- |
| ホームフォルダの `.claude/skills/スキル名/SKILL.md` | そのパソコンのすべてのプロジェクト |
| プロジェクトの `.claude/skills/スキル名/SKILL.md` | そのプロジェクトだけ |

ホームフォルダは、Windows なら `C:\Users\自分のユーザー名` です。僕のスキルは、ほとんどがこちらに置いてあります。アプリづくりも文章の決まりも、どのプロジェクトでも使うからです。

### 2. SKILL.md を書く

ファイルは2つの部分でできています。上の `---` で囲んだところが設定で、その下が手順です。僕の「Obsidian にメモを保存する」スキルを、形がわかるように短く書き直して載せます。

```markdown
---
name: obsidian-memo
description: Obsidian にメモを保存する。「メモして」「メモ残して」「ノートにまとめて」など、会話や調べた内容を残したいときは、Obsidian と言われていなくても必ずこのスキルを使う。
---

# Obsidian メモ

あとで見返したときに、一目でわかるメモを書く。

1. 何を残すかを決める
2. 決めた形（冒頭に要点、表は4列まで）で書く
3. 保存したら、ファイルの場所を伝える
```

設定の項目は、公式ドキュメントによるとすべて省略できます。ただし、`description` だけは書くよう勧められています。`name` を省いた場合は、フォルダの名前がそのままスキルの名前です。

僕は、このファイルを自分で一から書いていません。作業がうまくいったあとで、Claude Code に「いまの手順をスキルにして」と頼んで作ってもらいます。

### 3. 試す

試し方は2つです。

- 説明文に合う言葉で頼む（上の例なら「これメモして」）
- `/obsidian-memo` のように、名前で直接呼ぶ

スキルを書き換えると、開いている会話にもそのまま反映されます。新しいスキルが出てこないときは、`/reload-skills` を実行するよう公式ドキュメントに書いてあります。

## 説明文で、呼ばれるかどうかが決まる

Claude がふだん見ているのは、スキルの本文ではなく説明文です。本文は、呼ばれたときに初めて読み込まれます。つまり、説明文が合っていないと、どれだけ本文を作り込んでも使われません。

僕の説明文は、どれも次の3つを入れています。

1. 何をするスキルかを、最初の1文で言う
2. 自分が頼むときの言葉を「」で並べる（「アプリ作って」「〇〇アプリが欲しい」「スマホで使いたい」など）
3. 名前を言わなくても使ってほしい場面を書く（「形式の指定がなくても必ずこのスキルを使う」など）

2つ目は、公式ドキュメントの「スキルが呼ばれないとき」の確認項目とも重なります。そこには、利用者が自然に言う言葉が説明に入っているかを確かめる、とあります。

<Box type="warn" title="説明文は長くしすぎない">
スキルの一覧に出る説明は、1,536文字で切られます（公式ドキュメント）。大事な使い道は先頭に書きます。
</Box>

逆に、勝手に動いてほしくないスキルもあります。公開や送信のように、やり直しのきかない作業です。その場合は、設定に `disable-model-invocation: true` を足します。すると、`/スキル名` と打ったときだけ動きます。

## 本文は短く、細かいものは別のファイルに

公式ドキュメントは、`SKILL.md` を500行未満に保つよう勧めています。スキルは一度読み込まれると、その会話のあいだずっと残るからです。長いほど、毎回のやりとりが重くなります。

僕のスキルの行数を数えてみました。

| スキル | SKILL.md の行数 | 別に分けているもの |
| --- | --- | --- |
| アプリづくり | 261行 | 資料のフォルダ、スクリプト |
| 文章の決まり | 164行 | 文法の資料 |
| スキルを探す | 87行 | スクリプト |

フォルダの中は、こう分けています。

```text
app-creator/
├── SKILL.md        手順の流れだけ
├── references/     細かい資料。必要なときだけ読まれる
└── scripts/        決まった処理をするスクリプト
```

冒頭に書いた iPhone の余白の直し方は、スクリプトのほうに入れました。毎回 Claude に考えてもらうより、確かめた対策をそのまま実行してもらうほうが確実だからです。公式ドキュメントにも、スクリプトは「読み込まれず、実行される」ファイルだとあります。

分けたファイルは、`SKILL.md` の中で「くわしい決まりは `references/site.md`」のように名前を出しておきます。書いておかないと、Claude はそのファイルがあることに気づけません。

## 使いどころ：僕がスキルにした作業

11個のうち、よく使う4つです。

| スキル | 入れている手順 | 作ったきっかけ |
| --- | --- | --- |
| アプリづくり | 1つの HTML で作る、iPhone の表示の対策、バックアップ | iPhone の余白で、何度も公開し直した |
| 文章の決まり | 書く前に、使わない言い回しのリストを読む | 同じ言い回しを何度も指摘していた |
| 動画づくり | 台本、ナレーション、映像、サムネイルの順番 | 工程が多く、順番を決めておきたかった |
| メモの保存 | Obsidian のノートの形と書き込み方 | ノートの見た目をそろえたかった |

アプリづくりの話は「[Claude Code で iPhone のホーム画面アプリを作って無料公開する](/blog/claude-code-iphone-app/)」に、文章の決まりの話は「[Obsidian の使い方：AI と組み合わせてメモを整理する](/blog/obsidian-with-ai/)」に書いています。

### スキルにしないもの

何でもスキルにすると、数が増えて、どれが使われるのか見分けがつかなくなります。そこで「スキルを探す」スキルに、次の決まりを入れました。

- 合うスキルがあれば、それを使う
- 少し足りないだけなら、新しく作らずに、いまあるスキルを直す
- 一度きりの調べものや判断は、スキルにしない

迷ったら、作るより直す。直すより使う。似たスキルが2つできるのを防ぐための順番です。

<Box type="memo" title="毎回かならず守らせたい決まりは、フックへ">
スキルは、Claude が判断して使うものです。公式ドキュメントには、毎回守らせたい決まりを Claude が飛ばしてしまうなら、フック（決まったタイミングで自動で動く仕組み）に移すよう書いてあります。
</Box>

## うまく呼ばれないときに見るところ

公式ドキュメントの確認項目を、順番に並べます。

1. 説明文に、自分がふだん言う言葉が入っているか
2. Claude Code に「使えるスキルは？」と聞いて、一覧に出るか
3. `/スキル名` で直接呼ぶと動くか
4. `SKILL.md` の1行目が `---` で始まっているか。設定が壊れていると、名前で呼べても、説明文をもとにした自動の呼び出しはできなくなる

壊れたファイルを探すコマンドも用意されています。ホームフォルダのスキルなら `claude plugin validate ~/.claude/skills` です。

## 次にやること

1. Claude Code に何度も伝えている手順を、1つ思い出す
2. その作業がうまくいった直後に、「いまの手順をスキルにして」と頼む
3. できた `SKILL.md` の説明文を読み、自分が頼むときの言葉が入っているか確かめる

最初の1つは、10行ほどの短いスキルで十分です。使ってみて足りないところが見えたら、そのつど書き足していけば間に合います。Claude Code をまだ入れていない人は、「[Claude Code の始め方【Windows】](/blog/claude-code-windows-start/)」からどうぞ。
